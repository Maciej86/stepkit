# stepkit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Tasks 6–9 (skill text) additionally use superpowers:writing-skills.

**Goal:** Zbudować plugin Claude Code `stepkit` (polecenia `/stepkit:start` i `/stepkit:dalej`) razem z gotowym szkieletem aplikacji, który plugin kopiuje do projektu użytkownika, i opublikować go jako darmowy marketplace na GitHubie.

**Architecture:** Repo `skilsaas` jest marketplace'em z jednym pluginem w `plugins/stepkit/`. Plugin ma dwa skille (`start`, `dalej`) z krótkimi `SKILL.md` i szczegółami w `references/`, a obok nich folder `template/`: kompletny, przetestowany monorepo-szkielet (npm workspaces: `shared`, `backend`, `frontend`, `mockups`). Skille opisują proces; kod, który ma być zawsze taki sam (nawigacja według ról, middleware ról, walidacja, migracje, strona „Postęp”), siedzi w szablonie i ma testy.

**Tech Stack:** TypeScript, React + Vite, Mantine, react-router, i18next + react-i18next, Express, mysql2, zod, jsonwebtoken, bcryptjs, cookie-parser, helmet, cors, express-rate-limit, dotenv, tsx, concurrently, Vitest, Testing Library, supertest, @playwright/test, Docker Compose (MySQL 8.4 + phpMyAdmin; produkcyjnie + Caddy), `claude plugin validate` / `claude plugin eval`.

**Spec:** `docs/superpowers/specs/2026-11-11-plugin-budowa-aplikacji-design.md` (uporządkowany 2026-11-12; części aplikacji §5.3, wywiad §6.1, testy §7.2, e-mail §7.3, publikacja §7.4, zasady kodu §8, rozstrzygnięcia §11) (historia rozmowy: `docs/superpowers/specs/2026-11-11-skill-STAN-ROZMOWY.md`). Wzorzec: Antalo w `/home/maciej/www/register` (tylko do odczytu).

## Global Constraints

- Plugin: nazwa `stepkit`; skille `start` i `dalej`; pełne polecenia w każdym tekście dla użytkownika: `/stepkit:start`, `/stepkit:dalej`.
- **Nazwy w kodzie po angielsku [właściciel, 2026-11-12]:** foldery, pliki, funkcje, zmienne, typy, klucze modułów, adresy URL, tabele i kolumny bazy, nazwy plików w `docs/` i w `references/`. Po polsku zostaje wyłącznie to, co czyta człowiek: etykiety i komunikaty interfejsu, treść dokumentów i skilli, opisy commitów, wartości statusów w `STATUS.md`. Wyjątek: nazwy poleceń pluginu (`start`, `dalej`), bo to decyzja właściciela.
- **Stałe w plikach konfiguracyjnych [właściciel, 2026-11-12]:** żadnych „magicznych” liczb i tekstów w kodzie modułów. Wartości zmieniane tylko w kodzie trzymane w `shared/src/constants/` (używane przez front i backend: role, statusy, długości pól, limity), `backend/src/config/constants.ts` (tylko serwer: czas ważności tokenu, limity logowania, koszt bcrypt, rozmiar strony listy) i `frontend/src/config/constants.ts` (tylko interfejs). Stałe modułu w `shared/src/constants/<module>.ts`. `.env` wyłącznie na sekrety i ustawienia zależne od komputera (hasła, porty, adresy).
- Cała treść skilli, references, komunikatów, README i tekstów interfejsu szablonu: **po polsku, prostym językiem**, pojęcie techniczne wyjaśnione jednym zdaniem przy pierwszym użyciu.
- Odbiorca: Windows (natywnie, Git Bash) i macOS. Komendy w skillach muszą działać w Git Bash i w terminalu macOS. Bez instrukcji dla Linuksa.
- Stos narzucony, bez wyboru pakietów. Biblioteki „dopiero gdy potrzebne” (multer, cron, e-mail przez `nodemailer`, exceljs, winston, sanitize-html) **nie** wchodzą do szablonu.
- **Bez** Redux, redux-saga, styled-components.
- Trzy części aplikacji: strona publiczna `/` (bez logowania), konto użytkownika `/account` (role), panel administracyjny `/admin` (role); każda może być wyłączona przez `AREAS`.
- Porty: frontend `5173`, makiety `5174`, backend `3001`, MySQL na hoście `3307`, phpMyAdmin `8080`.
- `.env` zawsze w `.gitignore`; w repo tylko `.env.example`.
- Backend sprawdza rolę na każdej trasie modułu; menu tylko ukrywa pozycje.
- SQL wyłącznie z parametrami `?`; zmiany bazy wyłącznie jako migracje `NNN_nazwa.sql`.
- Format odpowiedzi błędu API: `{ "error": { "message": <klucz>, "fields"?: Record<string, <klucz>> } }` z właściwym kodem HTTP (400/401/403/404/503). Backend zwraca **klucze** z `SERVER_MESSAGES`, front tłumaczy. *(Antalo używało 200 + `error: true`; tu świadomie standardowe kody.)*
- **Teksty jako klucze [właściciel, 2026-11-12]:** żaden tekst dla człowieka w kodzie. Każdy tekst podany w tym planie w cudzysłowie („…”) trafia jako wartość do `shared/locales/pl/<namespace>.json` (namespace: `common`, `server`, `validation`, `email`, `<module>`), a kod używa klucza. Testy backendu sprawdzają klucze; testy frontu i makiet sprawdzają polski tekst (po załadowaniu `pl`).
- Język aplikacji na start: tylko `pl`, ale przez klucze (zob. wyżej). Wyjątek od „teksty jako klucze”: komunikaty konsoli w skryptach dla twórcy (`migrate`, `admin`, błąd braku `.env`) mogą być wpisane w kod po polsku.
- **Baza [właściciel, 2026-11-12]:** klucz obcy dla każdej relacji z regułą przy usunięciu (CASCADE / SET NULL + kopia nazwy / RESTRICT), archiwum (miękkie usuwanie) i historia zmian, gdy wywiad je potwierdzi; dokładne zasady w specu §8.
- Wymagane pluginy u użytkownika: superpowers (z zapasowymi wzorami, gdy instalacja się nie uda) i Playwright (blokuje start bez niego).
- Publikacja w internecie: ostatni moduł „Publikacja” (Mailgun z domeną + VPS OVH), spec §7.4. Makiety nigdy nie trafiają na serwer.
- Commity w tym repo po polsku, z linią `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **`docs/STATUS.md` poprawiany ręcznie przez użytkownika** (brak tabeli, dodatkowe kolumny, literówka w statusie): strona „Postęp” nie może się wysypać; pokazuje komunikat „Nie udało się odczytać docs/STATUS.md” i surową treść. Test w Task 4.

3. **Baza nie działa / brak `.env`** (Docker wyłączony): backend startuje, `/api/health` odpowiada, `/api/health/db` zwraca 503 z podpowiedzią „Czy Docker jest uruchomiony? (npm run db)”, zamiast crasha. Test w Task 2.
4. **Token z nieznaną rolą albo podpisany innym sekretem**: traktowany jak brak logowania, bez wyjątku; `canSee` zwraca `false` dla nieznanej roli. Testy w Task 1 i Task 2.
5. **Pozycja w `NAVIGATION` bez zarejestrowanego ekranu** (moduł dopisany do configu przed napisaniem ekranu): frontend i makiety pokazują „Ten ekran jeszcze nie powstał”, a nie biały ekran. Testy w Task 3 i Task 4.
